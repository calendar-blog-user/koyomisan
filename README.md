# こよみ通知アプリ（不特定多数向け・PWA版）

不特定多数の人が、アプリのインストールやアカウント登録をせずに使えることを目指した構成です。

**利用者の体験：**
1. リンクを開く
2. 「通知を受け取る」をタップして許可する
3. （お好みで）ホーム画面に追加する

以上です。アカウント登録・アプリのダウンロードは不要です。**通知は毎日ではなく、次のきっかけがある日だけ届きます（年間およそ140日、2〜3日に1回ほど）：二十四節気・七十二候の切り替わり／国民の祝日／重要な祭日／主要な年中行事／記念日。**通知には、利用者が選んだ都市（政令指定都市と東京）の日の出・日の入り・月の出・月の入りが添えられます。 サイト自体は毎日最新の内容に更新されるので、通知が来ない日でも開けばその日の暦が見られます。

## 仕組み

```
GitHub Actions（毎朝JST 6:47ごろに自動実行）
  ├→ ① サイトのデータを作る: 今日の暦情報を計算(天文計算 + コンテンツDB、LLM不使用)。
  │     今日の前日〜14日先ぶんを public/data/YYYY-MM-DD.json に、今日ぶんを today.json にも書き出す
  ├→ ② サイト(Firebase Hosting)を更新する  ← 通知より先に行う
  └→ ③ 通知のきっかけがある日だけ、Firestoreの全利用者へ、選んだ都市ごとの時刻を添えて
        Firebase Cloud Messaging経由でプッシュ通知を送信（年間およそ140日）

利用者のブラウザ
  ├→ サイトを開く → ブラウザの日付(日本時間)に合うデータを読む。無ければ today.json を読む
  ├→ 「通知を受け取る」ボタン → ブラウザの通知許可
  ├→ 「地点」で都市を選ぶと、日の出入り・月の出入りの表示と、通知に添える時刻がその都市のものに変わる
  └→ 許可されたトークンと選んだ都市をFirestoreに書き込む(読み取り不可の設定なので、他の人には見えません)
```

開発者側の初期設定さえ済ませれば、あとは完全に自動で、通知のきっかけがある日に通知が送られます。コードを書く必要はありません（コンソールでの設定のみ）。

## 初期セットアップ（開発者が一度だけ行う作業）

### 1. Firebaseプロジェクトを作る
1. https://console.firebase.google.com/ にアクセスし、Googleアカウントでログイン
2. 「プロジェクトを追加」→ 好きな名前を入力 → 作成（**無料のSparkプランのままでOK、クレジットカード登録は不要**）

### 2. Firestore・Hosting・Cloud Messagingを有効にする
1. 左メニュー「構築」→「Firestore Database」→「データベースの作成」→ リージョンは `asia-northeast1`（東京）がおすすめ → 本番環境モードで作成
2. 「ルール」タブを開き、このリポジトリの `firestore.rules` の中身を丸ごと貼り付けて「公開」
   - これにより、通知トークンと選んだ都市の「書き込み」だけが許可され、「読み取り」は誰にもできない状態になります(プライバシー保護)
   - **すでに以前のルールを設定している場合も、この手順で新しいルールに置き換えてください。**都市の変更を保存するために、更新を許可するルールが必要です
3. 左メニュー「構築」→「Hosting」→「始める」→ 表示される手順は一度画面を見るだけでOK（実際のデプロイはGitHub Actionsが自動で行うので、コマンド入力は不要です）

### 3. 通知用の鍵を発行する
1. 画面右上の歯車アイコン →「プロジェクトの設定」→「Cloud Messaging」タブ
2. 「ウェブ構成」の「ウェブ プッシュ証明書」で「鍵ペアを生成」をクリック → 表示された文字列をコピー（これが `VAPID_KEY`）

### 4. アプリの接続情報を取得する
1. 「プロジェクトの設定」→「全般」タブ → 下の方の「マイアプリ」→ `</>`（ウェブ）アイコンをクリック
2. アプリのニックネームを適当に入力して登録（Hostingの設定は不要）
3. 表示される `firebaseConfig = {...}` の中身をコピー

### 5. コード側に接続情報を書き込む
このリポジトリの `public/firebase-config.js` を開き、
- 手順4でコピーした `firebaseConfig` の値
- 手順3でコピーした `VAPID_KEY` の値

をそれぞれ書き換えて保存する。

### 6. サービスアカウントの鍵を発行する（GitHub Actionsがサーバー側で使う鍵）
1. 「プロジェクトの設定」→「サービス アカウント」タブ →「新しい秘密鍵の生成」→ JSONファイルがダウンロードされる
2. このファイルの中身（テキストエディタで開いてすべてコピー）を、次の手順でGitHubに登録する

### 7. GitHubリポジトリを作成してアップロードする
1. GitHubアカウントがなければ作成（https://github.com/join）
2. 新しいリポジトリを作成し、このフォルダの中身（`.github`フォルダも含む）を全てアップロードする

### 8. GitHubにシークレット・変数を登録する
リポジトリの `Settings` → `Secrets and variables` → `Actions` を開く

**Secrets タブ**（`New repository secret`）:
| Name | Value |
|---|---|
| `FIREBASE_SERVICE_ACCOUNT_JSON` | 手順6でダウンロードしたJSONファイルの中身を丸ごと貼り付け |

**Variables タブ**（`New repository variable`）:
| Name | Value |
|---|---|
| `FIREBASE_PROJECT_ID` | Firebaseのプロジェクトの設定→全般で確認できる「プロジェクトID」 |
| `SITE_URL` | `https://（プロジェクトID）.web.app` |

### 9. 初回実行
1. リポジトリの `Actions` タブ →「Daily Koyomi Notification」→「Run workflow」を押して手動実行
2. 数十秒〜1分ほどで完了。これで `https://（プロジェクトID）.web.app` が公開され、以降は毎日自動で実行され、通知のきっかけがある日に通知が送られます

### 10. 動作確認
1. スマホで `https://（プロジェクトID）.web.app` を開く
2. 「通知を受け取る」をタップして許可する
3. Firebaseコンソールの Firestore Database に `subscribers` コレクションが増えていれば登録成功

## 大切な注意点（iPhoneをお使いの方へ）

iPhone（Safari）では、Web上の通知を受け取るには**先にホーム画面に追加してから、そのアイコンで開く必要があります**（iOS 16.4以降の仕様）。トップページの「使いかた」にもこの案内を記載していますが、Android/PCでは特に手順を追加しなくても通知を許可するだけで動作します。

## 費用について

想定される利用規模（数百〜数千人程度）であれば、Firestore・Hosting・Cloud Messagingはすべて無料枠（Sparkプラン）の範囲内に収まります。クレジットカードの登録も不要です。

## うまく動かないときは

### サイトの日付が古いまま（昨日のまま）のとき
1. サイトの一番下の「データ更新：〇〇（日本時間）」を見てください。最後にデータが作られた日時です。
2. 日付が合っていないときは、サイトのカードに「表示しているのは〇〇の暦です」という注意が出ます。
3. GitHubの `Actions` タブで、最新の実行が赤い✕になっていないか確認してください。✕のときは、その実行を開いて、赤い行のエラーを確認します。
4. すぐに直したいときは、`Actions` → `Daily Koyomi Notification` → `Run workflow` を押してください（手動実行）。

朝の自動実行が遅れたり、1〜2日失敗したりしても、サイトは「今日の前日〜14日先」のデータを持っているので、正しい日付の暦が表示されます（15日以上止まると、古い日付が出ます）。通知の送信に失敗しても、サイトの更新は先に済んでいます。

### スマホで「通知を許可できない」とき
ボタンを押したあと、原因に応じた案内が画面に出ます。主な原因は次のとおりです。

| 原因 | 対処 |
|---|---|
| 以前に「ブロック」を選んだ／確認を何度か閉じた（Chrome） | アドレスバー左のアイコン →「サイトの設定」→「通知」を「許可」にして、ページを開き直す |
| スマホ本体でChromeの通知が止められている | 「設定」→「アプリ」→「Chrome」→「通知」をオンにする |
| LINE・SNSなどのアプリ内ブラウザで開いている | ChromeまたはSafariで、このページを開き直す |
| iPhoneのSafariで開いている | 先に「ホーム画面に追加」して、そのアイコンから開く（iOS 16.4以降） |

## 区分の考え方（通知のきっかけ）

| 区分 | 内容 | 通知 |
|---|---|---|
| 二十四節気・七十二候 | 候の切り替わり日（節気の切り替わりは、その初候の初日に含まれる） | する |
| 国民の祝日 | 祝日法の祝日。成人の日などの月曜移動、春分・秋分の日（天文計算）、振替休日、国民の休日を含む | する |
| 重要な祭日 | 宮中祭祀の主な祭儀（歳旦祭・元始祭・祈年祭・春秋の皇霊祭・神武天皇祭・神嘗祭・新嘗祭・大祓など） | する |
| 主要な年中行事 | 七草・鏡開き・小正月・節分・初午・ひな祭り・花まつり・端午・衣替え・七夕・お盆・十五夜・重陽・十三夜・七五三・冬至・正月事始め・大晦日 | する |
| 記念日 | 「〇〇の日」「原爆の日」など。国民の祝日や年中行事とは別の区分（収録は46件） | する |
| 雑節 | 彼岸・社日・八十八夜・入梅・半夏生・土用・二百十日など | しない（サイトには表示） |
| 六曜・選日 | 六曜は「今日の暦」に表示。一粒万倍日・天赦日・寅の日・巳の日・己巳の日・不成就日は、雑節・選日の欄に表示 | しない |
| 天文トピックス | 新月・上弦・満月・下弦の日時、日食・月食、流星群の極大。「月や星の暦・天文情報」に表示（該当する日は「今日の天文」にも表示） | しない |
| 昼の長さ | 日の出から日の入りまでの時間と、前日との差（地点ごと） | —（「今日の暦」に表示） |

主要な年中行事かどうかは `memorial_days.jsonl` の `major` と、`calendar_data.py` の `MAJOR_RULE_EVENTS` で変えられます。

## 通知の見え方

通知のタイトルは「今日は〇〇（区分）」の形で、**何の日だから通知しているのか**が分かるようにしています。本文には、きっかけを区分つきで1行ずつ並べ、最後に選んだ都市の日の出入り・月の出入りを添えます。

| きっかけ | タイトルの例 |
|---|---|
| 国民の祝日 | 今日は「文化の日」（国民の祝日） |
| 二十四節気 | 今日は二十四節気「寒露」の始まり |
| 七十二候(次候・末候) | 今日は七十二候「水始涸」（末候）の始まり |
| 年中行事 | 今日は「ひな祭り（上巳の節句）」（年中行事） |
| 重要な祭日 | 今日は「神嘗祭」（重要な祭日） |
| 記念日 | 今日は「目の日」（記念日） |
| 振替休日・国民の休日 | 今日は「振替休日」（休日） |
| きっかけが複数ある日 | 今日は「元日」（国民の祝日） ほか1件（本文に全件を区分つきで並べる） |

通知をタップして開くサイトの「今日の暦」にも、同じ言い方の見出し（例：「今日は「文化の日」（国民の祝日）」）が出ます。きっかけの優先順位は、国民の祝日 → 二十四節気 → 重要な祭日 → 年中行事 → 記念日 → 七十二候です。

## 計算の根拠と精度

- 日の出・日の入り・月の出・月の入り・南中は、国立天文台の定義に合わせて計算しています（太陽は上端・大気差35′、月は中心基準。時刻は分単位に四捨五入）。
  国立天文台 暦要項（東京の日出入、2026・2027年の148値）と照合し、**全値が±1分以内、完全一致は9割以上**です。「今日のこよみ」（東京・岡山）の6項目は完全一致でした。都市の座標は市役所付近のため、国立天文台の各地の表と1分程度の差が出ることがあります。
- 正午月齢は、直前の朔から正午までの日数で、国立天文台と同じく小数第1位まで表示します（例：27.98日 → 28.0）。
- 祝日（2026・2027年）と雑節（2026・2027年）は国立天文台 暦要項と、一粒万倍日の年間日数（2026〜2031年）・社日（2016〜2026年）は公表値と、完全に一致することを確認しています。
- 新月・上弦・満月・下弦の日時は、国立天文台 暦要項2026・2027年の朔弦望99件のうち**98件が完全一致、残り1件も1分差**です。天文計算ライブラリの月の位置が約4秒早いため、4秒の補正を入れています（2026年だけで決めても2027年が、2027年だけで決めても2026年が、同じ補正値で最良になることを確認）。
- 流星群の極大は、IMO(国際流星機構)の極大の太陽黄経から計算しています。国立天文台の2026年の予報(8件)と**すべて「時」まで一致**しました。月明かりの判定も、国立天文台の2026年の記述(6件)と一致しています。2027年以降は、同じ方法による予想です。
- 日食・月食は、国立天文台の公表一覧(「日本で見られる」ものだけ、2030年まで)をデータとして持っています。**毎年2月ごろに発表される暦要項に合わせて、`astro_events.py`の`ECLIPSES`を更新してください。**
- 天赦日(2026年の6日)・不成就日(2026年の複数月)・寅の日・巳の日・己巳の日は、公表されている日付と一致することを確認しています。
- 昼の長さ(日の出から日の入りまで)は、暦要項の東京の日出入(2026・2027年の74日)から求めた値と、全日±1分以内で一致します。
- 検証は `python verify_against_naoj.py` でいつでも再実行できます。

## 既知の課題・今後の拡張

- 祝日は現行の祝日法（2022年以降）の規定で計算しています。法改正があった場合は `calendar_extras.py` / `calendar_data.py` の見直しが必要です。
- 記念日は、裏付けの取れた46件のみです（それ以外の日は「該当なし」）。
- 七十二候のコンテンツ(72件)・記念日・神話などの文章は下書き段階です。固有名詞や事実関係は、記念日の一部を除いて個別の裏付け確認をしていません。
- 六曜・一粒万倍日・天赦日・寅の日・巳の日・不成就日は日本の暦注（民間の風習）で、科学的な根拠はありません。
- 10月りゅう座流星群は、年によって突然活発になることがあり、極大の日時は予想です。しし座流星群の「流星雨」も、起こる年は限られます。
- 日食・月食の一覧は2030年までです。それ以降は、国立天文台の発表に合わせて追加が必要です。
- 通知の実地テスト(絵文字・日本語の表示崩れ、1つだけ表示されるか、都市ごとの内容になっているか)は、実際にFirebaseへデプロイした上で確認してください(このチャットの実行環境からはFirebase/Googleのサーバーへの通信ができないため、ロジックの検証のみ行っています)。

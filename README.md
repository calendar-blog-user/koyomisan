# こよみ通知アプリ（不特定多数向け・PWA版）

不特定多数の人が、アプリのインストールやアカウント登録をせずに使えることを目指した構成です。

**利用者の体験：**
1. リンクを開く
2. 「通知を受け取る」をタップして許可する
3. （お好みで）ホーム画面に追加する

以上です。アカウント登録・アプリのダウンロードは不要です。**通知は毎日ではなく、七十二候が切り替わる日、または記念日がある日だけ届きます（年間およそ132回）。** サイト自体は毎日最新の内容に更新されるので、通知が来ない日でも開けばその日の暦が見られます。

## 仕組み

```
GitHub Actions（毎日JST7:00に自動実行）
  ├→ 今日の暦情報を計算(koyomi_engine.py + kou_content_72.jsonl、LLM不使用)
  ├→ サイト(Firebase Hosting)を最新の today.json で毎日更新
  └→ 七十二候が切り替わった日、または記念日がある日だけ、Firestoreに登録されている全利用者へ
     Firebase Cloud Messaging経由でプッシュ通知を送信（年間およそ132回）

利用者のブラウザ
  ├→ サイトを開く → 「通知を受け取る」ボタン → ブラウザの通知許可
  └→ 許可されたトークンをFirestoreに書き込む(読み取り不可の設定なので、他の人には見えません)
```

開発者側の初期設定さえ済ませれば、あとは完全に自動で毎日通知が送られます。コードを書く必要はありません（コンソールでの設定のみ）。

## 初期セットアップ（開発者が一度だけ行う作業）

### 1. Firebaseプロジェクトを作る
1. https://console.firebase.google.com/ にアクセスし、Googleアカウントでログイン
2. 「プロジェクトを追加」→ 好きな名前を入力 → 作成（**無料のSparkプランのままでOK、クレジットカード登録は不要**）

### 2. Firestore・Hosting・Cloud Messagingを有効にする
1. 左メニュー「構築」→「Firestore Database」→「データベースの作成」→ リージョンは `asia-northeast1`（東京）がおすすめ → 本番環境モードで作成
2. 「ルール」タブを開き、このリポジトリの `firestore.rules` の中身を丸ごと貼り付けて「公開」
   - これにより、通知トークンの「書き込み」だけが誰にでも許可され、「読み取り」は誰にもできない状態になります(プライバシー保護)
3. 左メニュー「構築」→「Hosting」→「始める」→ 表示される手順は一度画面を見るだけでOK（実際のデプロイはGitHub Actionsが自動で行うので、コマンド入力は不要です）

### 3. 通知用の鍵を発行する
1. 画面右上の歯車アイコン →「プロジェクトの設定」→「Cloud Messaging」タブ
2. 「ウェブ構成」の「ウェブ プッシュ証明書」で「鍵ペアを生成」をクリック → 表示された文字列をコピー（これが `VAPID_KEY`）

### 4. アプリの接続情報を取得する
1. 「プロジェクトの設定」→「全般」タブ → 下の方の「マイアプリ」→ `</>`（ウェブ）アイコンをクリック
2. アプリのニックネームを適当に入力して登録（Hostingの設定は不要）
3. 表示される `firebaseConfig = {...}` の中身をコピー

### 5. コード側に接続情報を書き込む
このリポジトリの `public/firebase-config.js` を開き、
- 手順4でコピーした `firebaseConfig` の値
- 手順3でコピーした `VAPID_KEY` の値

をそれぞれ書き換えて保存する。

### 6. サービスアカウントの鍵を発行する（GitHub Actionsがサーバー側で使う鍵）
1. 「プロジェクトの設定」→「サービス アカウント」タブ →「新しい秘密鍵の生成」→ JSONファイルがダウンロードされる
2. このファイルの中身（テキストエディタで開いてすべてコピー）を、次の手順でGitHubに登録する

### 7. GitHubリポジトリを作成してアップロードする
1. GitHubアカウントがなければ作成（https://github.com/join）
2. 新しいリポジトリを作成し、このフォルダの中身（`.github`フォルダも含む）を全てアップロードする

### 8. GitHubにシークレット・変数を登録する
リポジトリの `Settings` → `Secrets and variables` → `Actions` を開く

**Secrets タブ**（`New repository secret`）:
| Name | Value |
|---|---|
| `FIREBASE_SERVICE_ACCOUNT_JSON` | 手順6でダウンロードしたJSONファイルの中身を丸ごと貼り付け |

**Variables タブ**（`New repository variable`）:
| Name | Value |
|---|---|
| `FIREBASE_PROJECT_ID` | Firebaseのプロジェクトの設定→全般で確認できる「プロジェクトID」 |
| `SITE_URL` | `https://（プロジェクトID）.web.app` |

### 9. 初回実行
1. リポジトリの `Actions` タブ →「Daily Koyomi Notification」→「Run workflow」を押して手動実行
2. 数十秒〜1分ほどで完了。これで `https://（プロジェクトID）.web.app` が公開され、以降は毎日自動で通知が送られます

### 10. 動作確認
1. スマホで `https://（プロジェクトID）.web.app` を開く
2. 「通知を受け取る」をタップして許可する
3. Firebaseコンソールの Firestore Database に `subscribers` コレクションが増えていれば登録成功

## 大切な注意点（iPhoneをお使いの方へ）

iPhone（Safari）では、Web上の通知を受け取るには**先にホーム画面に追加してから、そのアイコンで開く必要があります**（iOS 16.4以降の仕様）。トップページの「使いかた」にもこの案内を記載していますが、Android/PCでは特に手順を追加しなくても通知を許可するだけで動作します。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `public/index.html` | 利用者が最初に開くページ。通知登録・ホーム画面追加の案内に加え、今日の暦の14セクション全文（季節の移ろい・農事歴・風習・記念日・神話・雑学・食材・花言葉・天文・工芸・祭事・芸能）をtoday.jsonから読み込んで表示 |
| `public/firebase-config.js` | Firebaseプロジェクトの接続情報(手順5で書き換える) |
| `public/firebase-messaging-sw.js` | バックグラウンドで通知を受け取るためのService Worker |
| `public/manifest.json` | PWAとしてホーム画面に追加するための設定 |
| `firestore.rules` | 通知トークンの「書き込みのみ許可・読み取り禁止」のセキュリティルール |
| `firebase.json` | Firebase Hostingの設定 |
| `koyomi_engine.py` | 旧暦・月齢・二十四節気・七十二候を計算する天文計算エンジン(国立天文台データで検証済み) |
| `kou_content_72.jsonl` | 七十二候ごとの解説文のデータベース |
| `render_koyomi.py` | 上記2つを結合し、指定フォーマットの文章を生成する |
| `notify_fcm.py` | 今日の暦情報を生成し、購読者全員にFCM経由で通知を送る本体 |
| `.github/workflows/daily-notify.yml` | 毎日自動実行するための設定(GitHub Actions) |

## 費用について

想定される利用規模（数百〜数千人程度）であれば、Firestore・Hosting・Cloud Messagingはすべて無料枠（Sparkプラン）の範囲内に収まります。クレジットカードの登録も不要です。

## 既知の課題・今後の拡張

- 🎌「日本の記念日と祝日」は72日分のみ収録（365日中）。それ以外の日は「該当する記念日は未収録」と表示されます
- 📚「日本の神話・伝説」セクション用のデータは未収録です
- 七十二候のコンテンツ(72件)・記念日データ(72件)はいずれも下書き段階のため、内容の事実確認や表現の見直しはまだ行っていません
- 通知の実地テスト(絵文字・日本語の表示崩れがないかなど)を、実際にFirebaseへデプロイした上で確認することをおすすめします(このチャットの実行環境からはFirebase/Googleのサーバーへの通信ができないため、ロジックの検証のみ行い、実際の送受信テストは未実施です)
